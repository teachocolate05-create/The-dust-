# THE DUST

폐쇄된 지하철 환승역을 복구해 생존 거점을 만드는 포스트 아포칼립스 생존 경영 시뮬레이션 (웹, PC·모바일)

## 현재 버전: 3단계 — 자원 및 시설 운영

### 실행 방법

[Node.js](https://nodejs.org) 20 이상이 설치되어 있어야 합니다.

```bash
npm install      # 처음 한 번만
npm run dev      # 개발 서버 실행 → 브라우저에서 http://localhost:3000
```

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발용 실행 (코드 수정이 바로 반영됨) |
| `npm run build` → `npm start` | 배포용 빌드 후 실행 |
| `npm test` | 게임 규칙 자동 테스트 |
| `npm run build:preview` | 설치 없이 열 수 있는 단일 파일 `preview/the-dust.html` 생성 (더블클릭으로 실행) |

### 플레이 방법

**하루 흐름**: 오전 → 오후 → 야간 (각 구간 행동 3회) → 정비 시간 (건설) → 다음 날

- **행동** 탭: 주변 탐색·자원 수집·식량 확보로 물자를 모읍니다. 행동마다 횟수 1을 씁니다.
- **잔해 정리**: 통로와 맞닿은 잔해를 눌러 치우면(2×2) 그 자리에 방을 지을 수 있고 자재도 얻습니다.
- **직접 수리**: 낮 구간에 시설을 선택하고 `직접 수리` (부품 1, 내구도 +25)
- **구간 종료**: 지도 위 `오전 종료 ▶` → 예상 자원 변화·경고를 확인하고 `진행`. 구간마다 식량·식수 1씩 소비
- **정비 시간**: 야간이 끝나면 시작. 행동 횟수 없이 방·시설을 건설하고 `정비 수리`를 합니다. 끝나면 `N일차 시작 ▶`
- **시설 운영**: 기계(발전기·정수 필터·작업대)는 가동 중 구간마다 자원을 쓰고/만들고 닳습니다. 시설 패널에서 `정지`/`가동`
- **저장 용량**: 자원마다 최대치가 있고 넘치면 버려집니다. 창고·탱크·사물함으로 늘립니다.
- **직접 제작**: 전력이 들어오는 작업대가 있으면 자재로 부품·고체 연료를 만듭니다.

### 건설 조작 (정비 시간)

- **지도 누르기**: 방·시설·타일을 선택해 오른쪽(모바일은 아래) 패널에서 정보를 봅니다.
- **방 만들기**: `건설` 탭 → 방 종류 선택 → 지도에서 드래그(모바일은 시작 칸, 끝 칸을 차례로 탭) → `건설`
- **시설 설치**: 방 선택 → `시설 설치` → 시설 선택 → 방 안을 눌러 위치 지정 → 같은 칸을 한 번 더 누르거나 `설치`. `회전`(PC는 R 키)
- **방 크기 변경**: 방 선택 → `크기 변경` → 위/아래/왼쪽/오른쪽 −/+ → `적용`
- **이동·회전·철거**: 시설 선택 후 패널 버튼 사용. 철거 시 비용의 50% 회수
- `Esc`: 작업 취소 · `개발 현황`: 구현된 기능과 예정 기능 확인 · `새 게임`: 처음부터

### 기능 구현 현황

| 기능 | 상태 |
|---|---|
| 지하철역 맵 (바닥·잔해·기둥·승강장·선로·출입구·급수원) | ✅ 작동 |
| 방 생성·크기 변경·이름/용도 변경·철거 (5종) | ✅ 작동 |
| 시설 설치·이동·회전·철거 (12종) | ✅ 작동 |
| 건설 비용 차감 / 50% 회수 | ✅ 작동 |
| 통로 연결 판정(출입 가능/고립)·출입문 표시 | ✅ 작동 |
| 자동 저장·새로고침 후 이어하기·저장 데이터 검증 | ✅ 작동 (기본) |
| 오전/오후/야간 → 정비 → 다음 날, 구간당 행동 3회 | ✅ 작동 |
| 행동: 주변 탐색·자원 수집·식량 확보·잔해 정리·직접 수리 | ✅ 작동 |
| 구간 종료 전 예상 변화·경고, 구간별 식량·식수 소비 | ✅ 작동 |
| 행동: 장소 조사·위험 제거·생존자 수색/구조 | ⏳ 5·6단계 (비활성 표시) |
| 저장 용량, 시설 가동/정지, 구간별 생산·소비, 전력 합계 | ✅ 작동 |
| 내구도 감소·효율 저하·고장, 직접 수리/정비 수리, 직접 제작 | ✅ 작동 |
| 전력선·수도관 연결 (지금은 전력을 전체 합계로 나눠 씀) | ⏳ 4단계 |
| 생존자 (탭 비활성) | ⏳ 5단계 |
| 무작위 사건 | ⏳ 6단계 |

> 시설 그래픽은 임시 이미지입니다. 식량이 바닥나도 아직 건강에는 영향이 없습니다(5단계에서 적용).

## 수치 바꾸기 (코드 몰라도 가능)

| 바꾸고 싶은 것 | 파일 |
|---|---|
| 맵 모양 | `src/game/config/map.ts` (글자 그림) |
| 시작 자원 | `src/game/config/resources.ts` |
| 방 비용·최대 크기·환급률·행동 횟수·식량 소비량 | `src/game/config/rules.ts` |
| 행동 획득량·탐색 결과표·야간 효율·제작법 | `src/game/config/actions.ts` |
| 기본 저장량 | `src/game/config/resources.ts` |
| 효율 단계·고장 확률·수리 비용 | `src/game/config/rules.ts` (`facility`) |
| 방 종류·최소 크기·색 | `src/game/config/rooms.ts` |
| 시설 크기·비용·성능 | `src/game/config/facilities.ts` |
| 시작 시 있는 방 | `src/game/state/initialState.ts` |

수정 후 `npm test`로 규칙이 깨지지 않았는지 확인하세요.

## 프로젝트 구조

```
src/
  app/                 Next.js 페이지와 전체 스타일 (globals.css)
  components/          화면(UI) — 지도, 상단 바, 패널, 작업 안내 바
  game/                게임 핵심 (UI와 분리)
    config/            수치·데이터
    core/              타입, 좌표 계산, 자원 계산
    systems/
      space.ts         방·시설 배치 규칙
      access.ts        통로·출입 판정
      phase.ts         시간 구간 규칙 (건설은 정비 시간에만, 행동은 낮에만)
      time.ts          구간 종료·예상치 계산·다음 날
      actions.ts       행동 실행과 결과
      operation.ts     저장 용량·시설 가동·생산/소비·전력·고장·수리
    state/             초기 상태, 상태 변경(reducer), 저장
tests/                 자동 테스트
```

**시스템 충돌 방지 설계**: 건설·배치는 `systems/phase.ts`의 `canModifyBase()`(정비 시간만), 행동은 `isDayPhase()`(낮 구간만)로 판단해 서로 겹치지 않습니다. 무작위 결과는 저장된 시드로 계산해 새로고침으로 결과를 바꿀 수 없습니다. 게임 상태는 `state/reducer.ts`를 통해서만 바뀝니다.
